# 05 — Known Stitch Export Issues & Resolutions (`05_KNOWN_STITCH_EXPORT_ISSUES.md`)

During our audit of the exported Stitch HTML screens (`Screen 03` through `Screen 08` in `stitch_vacatina_master_ui_foundation (23).zip`), the following generated JavaScript/DOM defects were identified and fixed in our modular implementation:

| # | Location in Stitch Export (`Screen 08 code.html`) | Defect Description | Resolution Implemented |
|---|---|---|---|
| 1 | Rail Journeys section (`#rail-journeys-section`) | Inline handlers call `filterRailCards(this, ...)` and `exploreRailRoute(...)` / `exploreAllRail()`, while the script block defined `filterRailJourneys` and `exploreRailJourney`. | Unified and wired both modular event listeners and backward-compatible handler functions so all Rail filter pills, card CTAs, and section-level CTAs work seamlessly. |
| 2 | Travel Insurance section (`#travel-insurance-section`) | Inline handlers call `filterInsuranceCards(this, ...)` and `exploreInsurance(...)`, while the script defined `filterInsurancePlans` and `selectInsurancePlan`. | Wired `filterInsuranceCards`, `filterInsurancePlans`, `exploreInsurance`, and `selectInsurancePlan` to the unified Insurance controller and configuration drawer. |
| 3 | Travel Insurance filter logic | `filterInsurancePlans` queried `#travel-insurance-grid > article[data-category]`, whereas the DOM cards use `data-insurance-category`. | Standardized filtering to match `data-insurance-category` / `data-category` and update the visible count pill accurately. |
| 4 | Cruises, Rails & Insurance favorite buttons | Inline handlers call `toggleSaveFavorite(this, '...')`, which was undefined in the global scope (`toggleSaveDiscovery` was defined instead). | Implemented unified `FavoritesService` with `toggleSaveFavorite`, `toggleSaveDiscovery`, and `toggleSaveInsurance` updating `aria-pressed`, visual state, toast notification, and the Saved Favorites drawer. |
| 5 | Holiday Package Details Modal | A later script block in `Screen 08` overwrote `window.viewHolidayPackageDetails` to click `#header-trip-bucket-btn` instead of opening `#holiday-package-details-modal`. | Restored `viewHolidayPackageDetails` to populate and open `#holiday-package-details-modal` with focus trap, `inert` background, and Escape/backdrop close, plus added a "Configure & Stage to Trip Bucket" workflow inside the modal. |
| 6 | Search Command Center prefill selectors | Discovery scripts queried `#panel-flights input[value*="London"]`, `#cars-pickup-display`, `#cars-servicetype-display`, etc., which did not match the static display spans in the Stitch HTML. | Built interactive, state-backed Search Command Center forms for all 11 tabs with real editable inputs, airport/destination selectors, date pickers, and Traveller/Cabin popover so prefill from any discovery card updates the exact fields and highlights the target panel. |
| 7 | Touch target sizing in JS class overwrites | `activateTab` and some filter scripts replaced `min-h-[44px]` with `min-h-[40px]` or `py-1.5` on state change. | Enforced `min-h-[44px]` (`>= 44x44px`) across all tabs, filter pills, header utilities, and interactive buttons in all active and inactive states. |
| 8 | Missing interactive Traveller selector & 8-state simulator | Static display text `2 Adults · Economy` had no interactive popover enforcing `Adults >= 1`, `Total <= 9`, `Infants <= Adults`, and `Screen 04` states were static HTML in a separate file. | Implemented the interactive Traveller & Cabin popover with full validation rules AND integrated the interactive 8-State Trip Bucket Engine + Screen 04 Component States Inspector directly into the application. |
